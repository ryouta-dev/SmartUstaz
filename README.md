# SmartУстаз — рабочее пространство преподавателя

Статическое браузерное приложение для подготовки плана занятия, конспекта, практических заданий и презентации. Русский и казахский интерфейс. Сервер приложения и сборка не требуются.

## Быстрый запуск

Распакуйте архив целиком. Для локального запуска из папки проекта:

```bash
python3 -m http.server 8000
```

Откройте http://localhost:8000. Просмотр интерфейса возможен и через index.html, но для API, загрузки файлов и предсказуемого хранения данных рекомендуется HTTP-сервер или GitHub Pages.

## Проверки

- `npm test` запускает локальные тесты Auth, AI gateway transport и облачного репозитория без внешних секретов.
- `npm run test:smoke` — браузерный сценарий. Нужны установленная dev-зависимость Playwright и браузер Chromium; сервер приложения должен быть запущен на `http://127.0.0.1:8765`.
- `npm run test:db` — pgTAP/RLS-тесты. Нужны Supabase CLI и запущенный локальный Supabase stack.
- Edge Functions, hosted RLS, реальный AI API, Telegram и мобильные браузеры требуют отдельной настройки/ручного тестирования; локальные unit-тесты не заменяют эти проверки.
- План настройки Supabase, Telegram, мобильной приёмки и отката: `docs/deployment-checklist.md`.

### Обновление GitHub Pages

1. В GitHub откройте Settings → Pages и выберите Deploy from a branch → `main` → `/ (root)`, если публикация ещё не настроена.
2. Дождитесь успешной публикации; ожидаемый адрес проекта: https://ryouta-dev.github.io/SmartUstaz/.
3. На телефоне откройте сайт и обновите страницу, если отображается старая версия.

Прототип Auth/gateway опубликован в `main`, но `supabase-config.js` намеренно оставлен пустым: без проекта Supabase вход и централизованный ИИ не заработают. При пустой конфигурации сохраняется legacy-режим с API-ключом, введённым отдельно на устройстве. После настройки Supabase вошедший пользователь может явно перенести шаблоны и текущий/предыдущий результат в облако с кнопки «Перенести в облако»; повторный импорт пропускает совпадения и не удаляет локальную копию. Кнопка «Загрузить из облака» добавляет облачные образцы в локальную библиотеку и сохраняет облачные занятия в отдельный JSON-бэкап, не заменяя текущий результат.

Добавлены серверные заготовки Telegram: `telegram-link` выдаёт одноразовую ссылку на 10 минут, а `telegram-webhook` проверяет secret header, приватный чат и дедуплицирует update ID. Для запуска нужны отдельный бот, Supabase secrets и HTTPS webhook; см. `docs/telegram.md`. `/new` пока только ведёт к сайту: интеграция общей генерации в Telegram ожидает серверный общий сценарий и реальный тест.

## Версия 2.1: ускоренная подготовка

1. По умолчанию создаётся компактный комплект: краткий план, конспект с заданиями и шесть коротких слайдов. Ограничены инструкции по объёму и число токенов вывода. Модель может не соблюдать заданный объём: это не жёсткий лимит слов.
2. Сначала создаётся план. Затем конспект и слайды отправляются **двумя параллельными запросами**, не ожидая друг друга. Это требует разрешения двух одновременных запросов у провайдера; если один вернёт 429, можно повторить только недостающий раздел.
3. Ответ читается потоком. Панель показывает время, состояние каждого раздела, число полученных знаков и черновой предпросмотр последних 3000 знаков текста. Итоговый JSON проверяется перед сохранением раздела. Текст рассуждений модели не показывается.
4. Готовый план сохраняется сразу, конспект и слайды — независимо друг от друга. Если вкладка закрыта или произошла ошибка, после открытия останется незавершённый комплект с кнопкой **«Досоздать недостающие разделы»**. Незаконченный текст внутри одного раздела не восстанавливается; этот раздел запрашивается заново.
5. Для деталей используйте **«Расширить конспект и задания»** и **«Расширить слайды и речь»**. Это отдельный запрос только для выбранного раздела. Перед заменой ваших правок запрашивается подтверждение. При ошибке старая версия остаётся.
6. В настройках можно отключить **«Получать ответ потоком»**, если API не поддерживает `stream: true`. Если сервер сам возвращает обычный JSON вместо SSE, он также обрабатывается. Если запрос со streaming отклонён сервером, автоматического повторного платного запроса нет — отключите режим вручную.
7. Во время генерации видны счётчик времени и кнопка отмены; предупреждение о медленном ответе появляется через 45 секунд без входящих данных. Новая схема ожидания: 5 минут без любых данных либо защитный максимум 30 минут на один запрос. При обычном JSON без потока отсутствие ответа тоже ограничено 5 минутами.

**Это не гарантия заданного времени генерации.** Реальная скорость Discovery/DeepSeek, режим рассуждений, очередь, лимиты аккаунта и буферизация потока прокси-провайдером в этой среде не измерялись. Если сервер буферизует ответ, текст может приходить крупными порциями.

Для повторного создания и расширения вместе с черновиком в браузере сохраняются исходные настройки занятия и выбранные образцы, но не API-ключ.

## Подключение Intern AI Discovery

Откройте **Настройки**:

- Провайдер: **Intern AI Discovery**.
- Base URL: `https://discovery-api.intern-ai.org.cn/v1`.
- API-ключ: ваш ключ. Ограничения вида `sk-or-...` отсутствуют.
- Идентификатор модели: **точное имя доступной вам модели из кабинета провайдера**. Не подставляйте произвольное имя: API должен его поддерживать.
- Нажмите **Сохранить настройки**, затем **Проверить подключение**.

Приложение отправляет POST на `<Base URL>/chat/completions`, передавая `Authorization: Bearer <ключ>`, `model`, `messages`, `stream: true` по умолчанию и лимит вывода `max_tokens` для генерируемых разделов. Не добавляйте `/chat/completions` в Base URL. Проверка подключения отправляет короткий запрос модели и может расходовать лимит.

**Важно:** реальное подключение к Discovery в среде разработки не проверено: внешняя сеть недоступна и рабочий ключ не предоставлен. Совместимость реализована на уровне OpenAI Chat Completions. Имена моделей, ограничения учётной записи и разрешения CORS нужно проверить у провайдера. Нет обещания совместимости с любым API: нужен именно поддерживаемый интерфейс.

Для OpenRouter выберите соответствующий профиль. Для другого совместимого сервиса выберите «Другой совместимый API» и заполните URL, ключ и модель. Приложение принимает любой непустой формат ключа; это **не обходит авторизацию** на сервере провайдера.

## Подключение River AI (только через серверный шлюз)

River AI (`https://api.river.ai/v1`) совместим с OpenAI Chat Completions, но **не отдаёт CORS-заголовки** и по документации требует хранить ключ на сервере. Поэтому в браузерном (legacy) режиме прямой вызов всегда упадёт с ошибкой сети/CORS. River AI нужно подключать через серверный шлюз Supabase:

1. Настройте проект Supabase и заполните `supabase-config.js` (URL проекта и publishable key) — тогда приложение переключится в режим шлюза, и поля провайдера в настройках станут недоступны.
2. Скопируйте `supabase/.env.example` в `supabase/.env` и задайте `AI_API_BASE=https://api.river.ai/v1`, `AI_API_KEY=rv_...`, `AI_MODEL=<точный id модели из River Console>` и `APP_ALLOWED_ORIGIN=<HTTPS-origin сайта без пути>`.
3. Загрузите секреты и разверните функцию: `supabase secrets set --env-file supabase/.env`, затем `supabase functions deploy ai-generate`.
4. Включите генерацию, установив `AI_GENERATION_ENABLED=true` (только после согласования бюджета), и войдите в аккаунт на сайте.

Ключ River при этом никогда не попадает в браузер. Подробности и список секретов — в `docs/ai-gateway.md` и `docs/deployment-checklist.md`.

### Если запрос не работает

- **401/403** — ключ, доступ к модели или учётной записи отклонены.
- **429** — превышен лимит запросов / квота.
- **HTTP 4xx/5xx** — проверьте адрес, идентификатор модели, баланс и состояние сервиса.
- **Ошибка сети/CORS** — проверьте интернет и разрешение запросов с домена сайта. CORS нельзя исправить только JavaScript-кодом на GitHub Pages: провайдер должен разрешить origin сайта. Альтернатива — отдельный доверенный backend, который в эту версию не входит.
- **5 минут без данных** — запрос прерывается, если API ничего не присылает. Таймер сбрасывается при каждом полученном фрагменте, включая служебные события.
- **30 минут на один запрос** — защитный предел даже при бесконечных служебных событиях. Общего ограничения в 120 секунд больше нет. Время в фоновой вкладке может отсчитываться браузером с задержкой.
- **Ответ обрезан / неверный JSON / неполные материалы** — попробуйте модель с большим лимитом вывода и лучшим соблюдением JSON.

## Хранение и безопасность

- По умолчанию ключ находится в памяти страницы и sessionStorage (сессия вкладки). Некоторые браузеры восстанавливают sessionStorage после восстановления закрытой сессии; для гарантированного удаления используйте кнопку «Удалить ключ».
- Постоянное хранение включается только флажком «Запомнить ключ на этом устройстве». localStorage **не зашифрован**; не включайте его на общем устройстве.
- Старый ключ OpenRouter автоматически читается для совместимости. Отключите запоминание и сохраните настройки либо удалите ключ, если не хотите сохранять его постоянно.
- При смене API-адреса приложение запрашивает подтверждение: ключ и материалы будут отправлены новому получателю.
- Разрешён HTTPS; HTTP — только для localhost/127.0.0.1/IPv6 loopback. URL с паролем, query-параметрами и fragment отклоняются. Редиректы API запрещены.
- Образцы, последний результат и его правки, язык, тема оформления и журнал времени хранятся в браузере. Очистка данных сайта удалит их. Не используйте персональные данные студентов.
- Образцы можно переносить JSON-файлом. Импорт ограничен 5 МБ / 200 записей, структуры нормализуются. Текстовые образцы обрезаются до 30 000 знаков, в запрос анализа попадают первые 24 000.
- Подключаемые сторонние скрипты выполняются в контексте страницы. Для рабочего использования с чувствительными данными рекомендуется самостоятельный аудит зависимостей и локальное размещение всех библиотек либо серверная архитектура.

## Экспорт и офлайн-режим

- Просмотр и редактирование примера, локальное хранение и экспорт образцов JSON не требуют API.
- Генерация и анализ образца требуют интернет и действительный ключ.
- PowerPoint: библиотека PptxGenJS включена локально в `vendor` с MIT-лицензией. Проверено скачивание и целостность PPTX с шестью слайдами. Ручная проверка учебного содержания и размещения длинного текста всё равно необходима.
- Word-экспорт и чтение DOCX используют исходные зависимости `docx@7.8.2` и `mammoth@1.6.0` с jsDelivr. Для них нужен доступ к CDN. Полная проверка Word-файла и чтения DOCX в текущей среде не выполнена: сеть заблокирована. Отсутствие библиотеки показывает понятное сообщение и не останавливает приложение.
- PDF напрямую не импортируется; текст можно скопировать вручную. Библиотека образцов принимает DOCX, TXT, MD, CSV. PPTX как исходный образец не читается: скопируйте текст слайдов.

## Проверки

Всего пройдено **40 сценариев**: 21 в `tests/smoke.cjs`, 11 проверок транспорта в `tests/transport.cjs`, 8 сквозных проверок в `tests/generation.cjs`. Транспорт и сквозные тесты используют настоящий локальный HTTP/SSE-сервер; подключения к внешней модели нет.

В `tests/smoke.cjs` — 21 регрессионный сценарий с **имитацией API**, без реальных ключей и расходов. Результат прогона: `tests/last-run.json`. Проверены генерация, отмена, ошибки 401/403, 429 и 500, сеть, усечение ответа, сохранение, импорт, переключение языка/темы, клавиатурная навигация, отсутствие горизонтального переполнения при ширинах 320/390/1440.

Для повторения тестов требуется Node.js и Playwright:

```bash
npm install
npx playwright install chromium
# В отдельном терминале:
python3 -m http.server 8765
# Затем:
npm test
```

При необходимости задайте путь к установленному Chromium через `CHROMIUM_PATH`. Браузерные проверки не заменяют тестирование с реальным API, Safari/iOS и вашим набором документов.

## Структура

- `index.html` — семантическая разметка и базовые стили компонентов.
- `styles.css` — новая дизайн-система и адаптивная компоновка.
- `app.js` — интерфейс, нормализация, хранение, параллельная генерация и экспорт.
- `api-client.js` — потоковый транспорт SSE/JSON, отмена и контроль ожидания.
- `vendor/` — локальная библиотека PowerPoint и лицензия.
- `tests/` — регрессионные тесты и журнал прогона.

Материалы ИИ — черновики. Перед занятием проверяйте расчёты, правовые ссылки, профессиональную терминологию и ответы к заданиям.

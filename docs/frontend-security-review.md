# SmartUstaz 3.0 — аудит безопасности frontend

Дата проверки: 2026-10-16

## Итог

**Подтверждённых уязвимостей высокого уровня уверенности в просмотренных frontend-потоках не выявлено.** Аудит статический: браузерные тесты недоступны, а код библиотек из `vendor/` и CDN не анализировался.

## Проверенные потоки

- Динамические `innerHTML` в `app.js`: список образцов, результаты, карточки генерации и варианты шаблонов. Строковые значения перед вставкой экранируются функцией `esc`; идентификаторы, используемые в HTML-атрибутах, также проходят экранирование.
- Результат модели разбирается как JSON, преобразуется через `normPlan`, `normNotes` и `normSlides`, а в HTML формируется через `ed`, которая экранирует отображаемый текст. Вставка в редактор принимает только `text/plain`.
- JSON-импорт образцов ограничен 5 МБ и 200 записями; профиль преобразуется через `cleanProfile`, которая выбирает фиксированный набор полей и ограничивает длины строк/массивов.
- Текстовые и DOCX-файлы ограничены 5 МБ, обрабатываются как текст; PDF отклоняется. Имя файла записывается в поле формы как значение DOM-свойства.
- Base URL AI-провайдера проверяется на HTTPS (HTTP допускается только для loopback), URL credentials/query/fragment отклоняются, HTTP-редиректы запрещены. API-ключ намеренно отправляется выбранному пользователем endpoint; UI предупреждает об отправке материалов и требует подтверждение при изменении Base URL.
- Ключ хранится в `sessionStorage` и может сохраняться в `localStorage` только по явному выбору. Это пользовательский ключ провайдера, не серверный секрет.

## Риски, не классифицированные как подтверждённые уязвимости

- DOCX-библиотеки подключаются с jsDelivr по фиксированным версиям, но без Subresource Integrity. Это риск цепочки поставок при компрометации CDN; в рамках данного аудита эксплуатируемый сценарий не подтверждён.
- Модель доверия статического приложения включает выбранный пользователем API-провайдер и исполняемые в origin библиотеки. Перед переходом к централизованному API ключи должны быть удалены из клиентской конфигурации, как предусмотрено планом.
- Не проверялись поведение браузерных расширений, реальные CSP/HTTP-заголовки хостинга, фактические данные браузерного профиля, содержимое скомпрометированного CDN, лимиты распаковки DOCX и сценарии на реальных браузерах.

## Проверенные участки

- `app.js`: экранирование и динамический рендеринг, нормализация результатов, импорт шаблонов, загрузка файлов, хранение ключа и валидация API URL.
- `api-client.js`: отправка секрета только на заданный endpoint, запрет редиректа, обработка SSE/JSON и ограничение размера ответа.
- `index.html`: типы полей, ограничения выбора файлов и внешние подключения скриптов.
